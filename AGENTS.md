# AGENTS.md — Afterglow Proof-First Rules

> Judge-mode is default. Assume every claim is fake until proven with logs.
> If it's not logged, timestamped, and re-runnable, it didn't happen.

This file governs all implementation work Oct 27 – Nov 4. Any agent or human
writing code in this repo MUST follow it. Violation = entry is disqualified
in our own eyes before a judge ever sees it.

## 0. Non-negotiables (read this 3 times)

1. **Real API calls only. No mocks, no canned responses, no regex diagnosis.**
   - Text API is the ONLY decider for diagnosis → patch.
   - If API is down, loop MUST fail loudly. Never fall back to heuristics silently.
2. **Every run MUST produce proof.** No proof = no claim.
3. **Small + true > big + shaky.** Target: 3 locked bugs green, 6/8 total. Honest reds stay visible.
4. **Foundation vs entry split is sacred.** Weft is referenced, never copied. See §7.

## 1. Proof bundle (required for EVERY green claim)

Every `runs/<run-id>/` MUST contain all of these, or the run is RED:

```
runs/<run-id>/
  artifacts/input_trace.txt      # exact 200-line failing window fed to model
  artifacts/boot.log             # full sim log BEFORE patch
  artifacts/boot_after.log       # full sim log AFTER patch
  artifacts/verdict_before.json  # builder verdict BEFORE
  artifacts/verdict_after.json   # builder verdict AFTER
  api/text_request.json          # exact prompt, prompt hash, model id, token count
  api/text_response.json         # raw response, latency ms, request id
  api/image_request.json         # failing window hash + diagnosis hash → image prompt
  api/image_response.json        # raw response + explain.png provenance
  explain.png                    # generated diagram, also embedded in report
  patch.diff                     # `git diff` output, allowlisted files only
  report.md                      # diagnosis verbatim, patch lines, checksums, cycles, time-to-green, retries
  meta.json                      # git sha, prompt hash, model ids, wall-clock start/end, sim seed
```

Rules:
- MUST log prompt hash (sha256), model id string, token counts, API latency, request ids.
- MUST log sim seed, cycle count, `tohost` value, checksums BEFORE and AFTER.
- MUST record wall-clock start/end in UTC. No "4m12s" without timestamps.
- NEVER edit a proof bundle after creation. Fix by creating a new run-id.
- `eval/score.py` MUST read ONLY from `runs/` bundles. No hand-typed scores.

## 2. Patch guardrails (enforced in `agent/guard.py`, shown in video)

A patch is ACCEPTED only if ALL pass:
- (a) touches allowlisted RTL files ONLY (list in `agent/allowlist.txt`)
- (b) ≤40 lines changed (`git diff --numstat` sum)
- (c) passes lint/compile (`make lint` exit 0)
- (d) is a real `git diff`, non-empty, no binary, no whitespace-only fix
- (e) max 2 retries per case, then case marked RED with logs kept

MUST show at least one REJECTED bad patch in `runs/` + in video. Rejected patches build trust.
NEVER allow: full-file rewrite, test-only fix that skips RTL, checksum hardcode, `tohost` force-pass.

Forbidden strings scan (CI MUST grep and fail):
- `tohost.*=.*1`, `PASS.*force`, `checksum.*hardcode`, `if.*test.*pass`
- Any patch that edits `eval/` or `repro/EXPECTED.md` to make green.

## 3. Collector discipline (anti-dump rule)

- Trace window ≤200 lines, total prompt ≤2500 tokens. Log exact counts.
- MUST include: failing fetch window + trap line + verdict.json. No full-log dumps.
- Every prompt lives in `agent/prompts/vX.txt` versioned. No inline prompts.
- Prompt changes require bump to vY + re-run of all 3 locked cases. No silent tuning.

## 4. Visual MUST be proven load-bearing (or we cut it)

`agent/visual.py` is NOT decoration. It MUST satisfy provenance:

- Input MUST be: hash of `input_trace.txt` + verbatim diagnosis text.
- Output MUST be: `explain.png` saved into same `runs/<id>/` BEFORE re-sim starts.
- `report.md` MUST embed `explain.png` + input hashes so judge can verify: this diagram came from THIS failure.
- Agent flow is: DIAGNOSE (text) → EXPLAIN (image) → PATCH. If image call fails, run continues but MUST be marked `explain: FAILED` in meta.json. No silent skip.

If by Oct 29 we cannot show a judge that the diagram helped a human verify the patch (e.g., highlights divisor vs baud), we CUT visual from claims and score as single-surface entry. Never claim "2 surfaces" without provenance.

## 5. Eval honesty (fix the math)

- Total is **8 cases**, not 10. NEVER write "8/10" again.
- Locked 3 (must be 3/3 green for main video): `picosoc-uart-div`, `picorv32-fetch-misalign`, `uart-tx-div`
- Stress 5 (2 reds OK): `uart-start-half`, `fetch-highword`, `rdata-latch`, `trap-stuck`, `pc-incr`
- Target: **locked 3/3, full 6+/8**. Publish `eval/results.md` generated by `eval/score.py`, never hand-edited.
- `eval/*.md` regenerate on every suite/CI run (timestamps + run timings); that dirt is expected, not scope creep — revert with `git checkout` unless the scorer legitimately changed rows.
- Scoring per case: `diagnosed? / fixed unaided? / sim reruns / time-to-green / patch lines / human touches (=0)`
- "Fixed unaided" = 0 human edits between RED and GREEN. Human pressing enter to run script is OK. Human editing RTL is instant disqualification of that case.

## 6. Repro: judge-proof one command

```bash
docker run ghcr.io/<you>/afterglow ./repro/run.sh --case picosoc-uart-div
```

- MUST go RED → agent (live API calls) → GREEN in <10 min on CPU-only laptop.
- MUST print BEFORE/AFTER checksums matching `repro/EXPECTED.md`.
- Live mode is DEFAULT for judging. Verify/replay mode exists ONLY for offline CI and MUST be labeled `mode: replay, not a claim`. NEVER present a replay log as a live green.
- Dockerfile MUST cache toolchain + frozen weft. Cold pull + run <10 min or it's broken.
- `repro/run.sh` MUST exit 1 on RED with `checksum MISMATCH`, exit 0 on GREEN with `checksum MATCH <sha>`. No exit 0 on partial.

Test rule: before Nov 1, at least one non-author human MUST run cold Docker green. Log their run-id in `repro/TESTED.md`.

## 8. Video proof rules (anti-edit suspicion)

- No cuts between PATCH diff shown and GREEN re-sim result. One continuous screen capture with wall-clock overlay.
- Timer overlay visible from RED to GREEN. Fast-forward allowed ONLY with `>> 8x` badge + preserved timer.
- Diagnosis card shown VERBATIM from `api/text_response.json`. No retyping.
- Checksums visible on screen, matching `EXPECTED.md` + `runs/` bundle.
- Captions required. No talking head. 180s exactly.
- Test on one non-hardware viewer before lock. If they can't repeat the one-liner ("AI fixed a chip by reading traces"), recut.

## 9. Energy/impact honesty

- Claim ONLY: "faster bring-up → fewer engineer-hours, fewer respins." Back with time-to-green numbers.
- NEVER claim measured watt savings without measurement. No "less energy per chip" unless we log joules.
- One-liner for submission (150 words max): problem → loop → numbers (3/3 + 6/8, time-to-green, checksums) → open-silicon CTA.

## 10. Agent workflow (how to work in this repo)

When implementing ANY feature:

1. Read PLAN.md + this file. State which eval case it serves.
2. Write code + proof logging first, not code alone. If `runs/` bundle incomplete, feature is incomplete.
3. Run `eval/score.py` after every prompt change. Paste numbers in commit message.
4. NEVER weaken a guardrail to get green. Fix the prompt/collector, not the test.
5. NEVER edit `EXPECTED.md`, `results.md`, or old `runs/` to make green. Create new runs.
6. Before claiming done: `ls runs/<id>/` has all 11 files? `patch.diff` ≤40 lines? `meta.json` has zero human touches? If no, keep working.
